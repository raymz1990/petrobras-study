Destaques Cesgranrio — Argumentos

  • Modus Ponens: P→Q, P ⊢ Q. Modus Tollens: P→Q, ¬Q ⊢ ¬P — os dois mais cobrados
  • Falácias: Afirmação do Consequente (P→Q, Q ⊢ P) e Negação do Antecedente (P→Q, ¬P ⊢ ¬Q) — INVÁLIDAS

  • Decidibilidade: lógica sentencial é decidível (tabela-verdade); predicados de 1ª ordem é semi-decidível
  • Tautologia: sempre V. Contradição: sempre F. Contingência: depende dos valores

Argumentos Lógicos

⭐ Definição de Argumento
Um argumento é um conjunto de proposições onde algumas (as premissas) são apresentadas como justificativa para outra (a conclusão). Notação: P₁, P₂, ..., Pₙ ⊢ C (⊢ = "portanto"/"logo").

Validade vs Verdade

ConceitoDefiniçãoDepende de
Argumento Válido É IMPOSSÍVEL que todas as premissas sejam verdadeiras e a conclusão seja falsa. A forma lógica está correta. Estrutura formal (forma)
Argumento Sólido (Sound) É válido E todas as premissas são verdadeiras. Garante conclusão verdadeira. Forma + conteúdo
Argumento Inválido (Falácia) É possível ter premissas verdadeiras e conclusão falsa. A forma lógica está errada. Estrutura formal (forma)
⚠️ Validade ≠ Verdade das premissas
Um argumento pode ser VÁLIDO mesmo com premissas FALSAS:
"Todo gato tem asas (F). Rex é um gato (F). Logo, Rex tem asas." → VÁLIDO (a forma é correta: todo A é B, x é A, logo x é B)

Um argumento pode ter premissas VERDADEIRAS e ser INVÁLIDO:
"O sol é uma estrela (V). A lua orbita a Terra (V). Logo, o sol tem satélites." → INVÁLIDO (as premissas não sustentam a conclusão)

Como Verificar Validade

1

Método da Tabela-Verdade

Construir a tabela-verdade de todas as premissas e da conclusão. Se em TODA linha onde todas as premissas são V a conclusão também é V → argumento válido.

2

Método da Contradição (Refutação)

Assumir que as premissas são V e a conclusão é F. Se isso gerar contradição → argumento válido. Se for consistente → inválido.

3

Reconhecimento de Forma

Identificar se o argumento corresponde a uma regra de inferência válida conhecida (MP, MT, SH, SD...) ou a uma falácia conhecida.

Formas Canônicas de Argumento

Notação de argumentos
Argumento válido — Modus Ponens:
  P₁: P → Q    (Se P então Q)
  P₂: P        (P é verdadeiro)
  ────────────
  C:  Q        (Logo, Q é verdadeiro)

Contra-exemplo para invalidar um argumento:
Encontrar atribuição de valores onde P₁=V, P₂=V, mas C=F
Se tal atribuição EXISTIR → argumento INVÁLIDO
Se NÃO EXISTIR → argumento VÁLIDO

Regras de Inferência Válidas

RegraForma SimbólicaExemplo Concreto
Modus Ponens (MP) P→Q, P ⊢ Q "Se há falha (P), o sistema trava (Q). Há falha. Logo, o sistema trava."
Modus Tollens (MT) P→Q, ¬Q ⊢ ¬P "Se há falha (P), o sistema trava (Q). O sistema não travou (¬Q). Logo, não houve falha (¬P)."
Silogismo Hipotético (SH) P→Q, Q→R ⊢ P→R "Se chuva → lama. Se lama → atraso. Logo, se chuva → atraso."
Silogismo Disjuntivo (SD) P∨Q, ¬P ⊢ Q "A ou B. Não A. Logo, B."
Adição (Ad) P ⊢ P∨Q "A é verdadeiro. Logo, A ou B é verdadeiro." (qualquer Q)
Simplificação (Simp) P∧Q ⊢ P "A e B são verdadeiros. Logo, A é verdadeiro."
Conjunção (Conj) P, Q ⊢ P∧Q "A é V. B é V. Logo, A e B são verdadeiros."
Dupla Negação (DN) ¬¬P ⊢ P "Não é falso que A. Logo, A é verdadeiro."
Dilema Construtivo (DC) P→Q, R→S, P∨R ⊢ Q∨S "Se A→B e C→D e (A ou C), então (B ou D)."

Modus Ponens vs Modus Tollens — Detalhe

✅
Modus Ponens
Afirma o antecedente → afirma o consequente. "P→Q, P ⊢ Q". Direção: frente. Válido.
✅
Modus Tollens
Nega o consequente → nega o antecedente. "P→Q, ¬Q ⊢ ¬P". Equivale à contrapositiva. Válido.
❌
Falácia do Consequente
Afirma o consequente → tenta afirmar o antecedente. "P→Q, Q ⊢ P". INVÁLIDO.
❌
Falácia do Antecedente
Nega o antecedente → tenta negar o consequente. "P→Q, ¬P ⊢ ¬Q". INVÁLIDO.

Prova Formal — Exemplo

Prova formal passo a passo
Premissas:
  1. P → Q
  2. Q → R
  3. P

Provar: R

Demonstração:
  4. P → R     (Silogismo Hipotético: 1, 2)
  5. R         (Modus Ponens: 4, 3)   ■

Leitura: "Se P então Q. Se Q então R. P é verdadeiro.
Logo, há um caminho P→Q→R, e como P é V, R deve ser V."

❌
Falácias Lógicas Formais

💡 O que é uma Falácia Formal
Falácia formal é um argumento inválido que parece válido à primeira vista — a forma lógica está errada, mas o raciocínio parece plausível. É diferente de falácia informal (que envolve conteúdo, não forma).

As 2 Falácias Formais Mais Cobradas

❌ Falácia da Afirmação do Consequente
Forma inválida
P₁: P → Q    (Se P então Q)
P₂: Q        (Q é verdadeiro)
────────────
C:  P        (Logo, P é verdadeiro)  ← INVÁLIDO!

Por que é inválido: Q pode ser verdadeiro por outras razões além de P.

Exemplo: "Se chove (P), a rua fica molhada (Q). A rua está molhada (Q). Logo, choveu (P)." → INVÁLIDO: pode ter sido o caminhão-pipa.

Confunde com Modus Ponens
MP afirma o ANTECEDENTE (P) para concluir o consequente (Q). A falácia afirma o CONSEQUENTE (Q) para concluir o antecedente (P) — sentido invertido, forma inválida.
❌ Falácia da Negação do Antecedente
Forma inválida
P₁: P → Q    (Se P então Q)
P₂: ¬P       (P é falso)
────────────
C:  ¬Q       (Logo, Q é falso)  ← INVÁLIDO!

Por que é inválido: Só porque P é falso, não significa que Q também é. Q pode ser verdadeiro por outro motivo.

Exemplo: "Se chove (P), a rua fica molhada (Q). Não choveu (¬P). Logo, a rua não está molhada (¬Q)." → INVÁLIDO: pode ter sido o irrigador automático.

Confunde com Modus Tollens
MT nega o CONSEQUENTE (¬Q) para concluir a negação do antecedente (¬P). A falácia nega o ANTECEDENTE (¬P) para concluir a negação do consequente (¬Q) — ordem invertida, forma inválida.

Sistemas Dedutivos e Decidibilidade

O que é um Sistema Dedutivo

Um sistema dedutivo (ou sistema formal) é composto por:

📋
Alfabeto
Conjunto de símbolos básicos: variáveis proposicionais, conectivos, parênteses.
📏
Regras de Formação
Definem quais sequências de símbolos são fórmulas bem-formadas (fbf).
🌱
Axiomas
Fórmulas aceitas como verdadeiras sem prova — ponto de partida do sistema.
🔧
Regras de Inferência
Permitem derivar novas fórmulas a partir de fórmulas já provadas.

Propriedades dos Sistemas Formais

PropriedadeDefinição
Correção (Soundness)Tudo que é provável no sistema é logicamente válido. "Não prova falsidades."
Completude (Completeness)Tudo que é logicamente válido pode ser provado no sistema. "Nada válido escapa."
ConsistênciaNão é possível provar P e ¬P ao mesmo tempo — sem contradições internas.
DecidibilidadeExiste algoritmo que determina em tempo finito se qualquer fórmula é teorema ou não.

Decidibilidade — Lógica Sentencial vs Predicados

SistemaDecidibilidadePor quê
Lógica Sentencial (Proposicional) ✅ DECIDÍVEL A tabela-verdade é um algoritmo que determina em tempo finito (2ⁿ linhas) se qualquer fórmula é tautologia, contradição ou contingência.
Lógica de Predicados de 1ª Ordem ⚠️ SEMI-DECIDÍVEL Pode-se provar que uma fórmula É válida (enumeração de provas), mas não existe algoritmo geral para provar que uma fórmula NÃO É válida em tempo finito. (Teorema de Church, 1936)
💡 Implicação da Semi-Decidibilidade
Na lógica de predicados, se você quer provar que "∀x P(x)" é válida, pode encontrar uma prova. Mas se for inválida, pode procurar para sempre sem encontrar um contra-exemplo — o algoritmo pode não parar. Por isso é semi-decidível: funciona para respostas "sim", mas não garante parada para respostas "não".

Valores-Verdade e Funções de Avaliação

Uma função de avaliação (ou valoração) atribui valores-verdade às proposições atômicas. Para uma fórmula com n variáveis, existem 2ⁿ valorações possíveis.

Avaliação de fórmula complexa
Fórmula: (P → Q) ∧ (¬Q → R)
Valoração: P = V, Q = F, R = V

Passo 1: P → Q = V → F = F
Passo 2: ¬Q = ¬F = V
Passo 3: ¬Q → R = V → V = V
Passo 4: F ∧ V = F

Resultado: a fórmula é FALSA nesta valoração.
→ Não é tautologia (há ao menos uma valoração que a falsifica)

Exercícios Modelo — Raciocínio Completo

🧩 Problema 1 — Identificar a regra de inferência

Enunciado: "Toda vez que o sistema está sob carga (P), ele responde lentamente (Q). O sistema não está respondendo lentamente (¬Q). Portanto, o sistema não está sob carga (¬P)."

Identificação:

Formalização
P₁: P → Q    (carga → resposta lenta)
P₂: ¬Q       (não responde lentamente)
─────────────
C:  ¬P       (não está sob carga)

Forma: P→Q, ¬Q ⊢ ¬P = MODUS TOLLENS ✅ VÁLIDO
🧩 Problema 2 — Identificar falácia

Enunciado: "Se há um ataque SQL Injection (P), o banco de dados é comprometido (Q). O banco de dados foi comprometido (Q). Logo, houve um ataque SQL Injection (P)."

Formalização
P₁: P → Q    (SQLi → BD comprometido)
P₂: Q        (BD comprometido)
─────────────
C:  P        (houve SQLi)

Forma: P→Q, Q ⊢ P = AFIRMAÇÃO DO CONSEQUENTE ❌ INVÁLIDO

Por quê: o BD pode ter sido comprometido por outro ataque
(XSS, acesso físico, credenciais roubadas) — Q pode ser V
mesmo com P sendo F.
🧩 Problema 3 — Silogismo hipotético

Enunciado: "Se o backup falha (P), os dados são perdidos (Q). Se os dados são perdidos (Q), a operação para (R). Portanto, se o backup falha (P), a operação para (R)."

Formalização
P₁: P → Q    (backup falha → dados perdidos)
P₂: Q → R    (dados perdidos → operação para)
─────────────
C:  P → R    (backup falha → operação para)

Forma: P→Q, Q→R ⊢ P→R = SILOGISMO HIPOTÉTICO ✅ VÁLIDO

O termo intermediário Q é "eliminado" — encadeamento válido.
