Ataques & Malwares

Softwares maliciosos (ransomware, vírus, worms, spyware, rootkit), ataques web (DDoS, SQLi, XSS, CSRF, Path Traversal) e técnicas de desenvolvimento seguro (SAST/DAST/IAST).

⏱ ~50 min
🎯 Alta incidência
👑

Destaques Cesgranrio — Ataques

  • Worm se propaga sozinho pela rede; vírus precisa de hospedeiro; trojan precisa de ação do usuário
  • Stored XSS é persistente (armazenado no servidor); Reflected XSS é imediato (via URL)
  • CSRF usa a sessão autenticada do usuário — diferente do XSS que injeta script
  • SQL Injection: solução é Prepared Statement, não apenas validação de entrada
  • DDoS viola Disponibilidade; vazamento viola Confidencialidade; alteração viola Integridade
  • Engenharia social explora o fator humano — phishing é o tipo mais comum

Softwares Maliciosos

MalwareComo se propagaAção principalPilar CID
Vírus Anexa-se a arquivos legítimos — propaga quando arquivo é executado pelo usuário Corrompe/modifica arquivos, replica Integridade
Worm Auto-propaga pela rede SEM interação humana — explora vulnerabilidades de serviços Consome recursos, instala backdoors, propaga outros malwares Disponibilidade
Trojan (Cavalo de Troia) Disfarçado de software legítimo — usuário instala voluntariamente Abre backdoor, roubo de dados, download de outros malwares Confidencialidade
Ransomware Via email (phishing), exploit, download malicioso Criptografa arquivos e exige resgate (geralmente criptomoeda) Disponibilidade (+ Confidencialidade)
Spyware Instalado junto com software gratuito (bundleware) Monitora comportamento, captura senhas, histórico, keylogging Confidencialidade
Rootkit Via exploits, trojans ou instaladores comprometidos Oculta presença de outros malwares, garante acesso privilegiado persistente Confidencialidade + Integridade
Adware Bundleware, downloads gratuitos Exibe anúncios não solicitados, coleta dados de navegação Confidencialidade
Botnet Via worm, trojan ou exploit Transforma o dispositivo em "zumbi" controlado remotamente (C&C) para DDoS, spam Disponibilidade (de vítimas)
⭐ Distinção Chave — Vírus vs Worm vs Trojan
Vírus: precisa de um arquivo HOSPEDEIRO para se anexar + ação do usuário para executar.
Worm: independente, auto-propaga pela REDE sem hospedeiro e sem interação humana.
Trojan: não se replica — parece legítimo mas executa ação maliciosa oculta. Depende do usuário instalar.

Resumo: Vírus = arquivo; Worm = rede autônomo; Trojan = disfarce.

APT — Advanced Persistent Threat

💡 APT — Ameaça Persistente Avançada
Ataques sofisticados, geralmente patrocinados por estados, que permanecem ocultos por longo tempo (meses/anos) coletando dados estratégicos. Características: furtivos, direcionados, persistentes, com múltiplas fases (reconhecimento → comprometimento inicial → persistência → movimentação lateral → exfiltração).

Ataques a Aplicações Web

💉 SQL Injection (SQLi)

Insere código SQL malicioso em campos de entrada para manipular queries do banco.

Exemplo de ataque
-- Formulário de login vulnerável
SELECT * FROM users WHERE user='$login' AND pass='$senha'

-- Ataque: login = admin'--  (comenta o restante)
SELECT * FROM users WHERE user='admin'--' AND pass=''
-- Acesso sem senha!

-- Ataque com UNION para exfiltrar dados
' UNION SELECT username, password FROM users--
✅
Prevenção
Prepared Statements / Parameterized Queries, ORM, validação de entrada, WAF, princípio do menor privilégio no banco.
🎯
Pilar violado
Confidencialidade (exfiltração de dados) e Integridade (alteração/deleção de registros).
🖥️ XSS — Cross-Site Scripting

Injeta scripts maliciosos em páginas web que são executados no navegador de outras vítimas.

TipoComo funcionaPersistência
Stored (Persistente)Script salvo no banco de dados do servidor — executado a cada visualização da página✅ Alta — afeta múltiplos usuários
ReflectedScript na URL — retornado imediatamente na resposta do servidor❌ Baixa — requer clicar no link malicioso
DOM-basedScript manipula o DOM no cliente — não passa pelo servidor❌ Baixa

Prevenção: Output encoding (HTML entity encoding), Content Security Policy (CSP), validação de entrada, HttpOnly cookies.

🔄 CSRF — Cross-Site Request Forgery

Engana um usuário autenticado a executar ações indesejadas em um site confiável.

1

Vítima está logada no banco.com

Sessão autenticada com cookie válido.

2

Vítima visita site malicioso

Site malicioso contém formulário ou imagem que faz requisição para banco.com.

3

Navegador envia cookie automaticamente

banco.com recebe requisição com cookie válido → executa a ação (ex: transferência).

Prevenção: CSRF token (token único por formulário), SameSite cookie attribute, verificar Origin/Referer header, re-autenticação para ações críticas.

XSS vs CSRF
XSS injeta código que executa no navegador da vítima (atacante controla o browser). CSRF usa a sessão da vítima para fazer requisições não autorizadas em site legítimo (atacante não vê a resposta). XSS é do lado cliente; CSRF explora confiança do servidor.
🌊 DDoS — Distributed Denial of Service

Inunda o alvo com tráfego de múltiplas origens (botnet) até tornar o serviço indisponível.

TipoVetor
VolumétricoSatura largura de banda (UDP flood, ICMP flood). Medido em Gbps.
ProtocoloExplora fraquezas de protocolos (SYN flood — esgota conexões TCP).
Camada de AplicaçãoHTTP flood — requisições GET/POST em volume que esgotam recursos do servidor.

Mitigação: CDN, scrubbing centers, rate limiting, anycast routing, WAF com proteção DDoS, black-holing.

📁 Path Traversal

Acessa arquivos fora do diretório permitido usando sequências ../ (dot-dot-slash).

Exemplo
-- URL vulnerável
GET /download?file=report.pdf

-- Ataque: navega para fora do diretório
GET /download?file=../../../etc/passwd
GET /download?file=..\..\windows\system32\config\sam

-- Objetivo: acessar arquivos de configuração, senhas do sistema

Prevenção: Validar e sanitizar parâmetros de arquivo, usar caminhos absolutos resolvidos, whitelist de arquivos/extensões permitidos, nunca usar input do usuário diretamente em caminhos de arquivo.

🤝 Man-in-the-Middle (MitM)

Atacante intercepta a comunicação entre duas partes sem que nenhuma perceba.

Técnicas: ARP Spoofing (rede local), DNS Spoofing, SSL Stripping (downgrada HTTPS para HTTP).

Viola: Confidencialidade (lê os dados) e Integridade (pode alterar os dados em trânsito).

Prevenção: HTTPS + HSTS (HTTP Strict Transport Security), certificate pinning, VPN, verificar certificados digitais.

Engenharia Social

Engenharia social explora o fator humano — manipula pessoas para que revelem informações ou executem ações que comprometam a segurança. É frequentemente a porta de entrada de ataques sofisticados.

TécnicaComo funciona
PhishingEmail fraudulento imitando entidade legítima (banco, Petrobras, Receita Federal) para roubar credenciais
Spear PhishingPhishing direcionado a pessoa específica com informações personalizadas — mais convincente
WhalingSpear phishing direcionado a executivos (CEO, CFO) — alto valor
VishingPhishing por voz — ligação telefônica fraudulenta
SmishingPhishing por SMS
PretextingCria cenário fictício para obter informações ("Sou do suporte, preciso da sua senha")
BaitingIsca física (pendrive na recepção) ou digital (download gratuito com malware)
TailgatingAcesso físico não autorizado seguindo funcionário legítimo por porta controlada
💡 Por que engenharia social é tão eficaz?
Explora características humanas: autoridade ("sou o gerente de TI"), urgência ("sua conta será bloqueada em 1h"), curiosidade, medo e confiança. A tecnologia é mais fácil de proteger do que as pessoas — daí a frase: "O elo mais fraco na segurança é o humano."

Práticas de Desenvolvimento Seguro

🛡️
Menor Privilégio
Cada componente tem apenas as permissões mínimas necessárias. BD: usuário da app sem permissão de DROP.
🔍
Validação de Entrada
Validar TUDO que vem do cliente (tipo, tamanho, formato, range). Nunca confiar em input do usuário.
📝
Prepared Statements
Parâmetros separados da query SQL — previne SQL Injection de forma definitiva.
🔒
Criptografia em Repouso/Trânsito
HTTPS para dados em trânsito. AES-256 para dados armazenados. Hashing de senhas (bcrypt, Argon2).
🔑
Gestão Segura de Segredos
Nunca hardcode de senhas no código. Usar cofres de segredos (HashiCorp Vault, AWS Secrets Manager).
📋
Threat Modeling
STRIDE/DREAD na fase de design para identificar ameaças antes de codificar. Barato prevenir vs corrigir.
