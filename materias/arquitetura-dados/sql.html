SQL, DDL & DML

Linguagem SQL completa: consultas, junções, subconsultas, funções de agregação, DDL (CREATE/ALTER/DROP) e DML (INSERT/UPDATE/DELETE). O tópico mais cobrado do Bloco I.

O que a Cesgranrio mais cobra em SQL

  • Resultado de SELECT com JOIN — a banca mostra o schema e pede o output
  • WHERE vs HAVING — WHERE filtra linhas, HAVING filtra grupos após GROUP BY
  • INNER JOIN vs LEFT JOIN — diferença no resultado quando há registros sem correspondência
  • Subconsultas com IN, EXISTS, ANY, ALL — identificar qual retorna o resultado correto
  • TRUNCATE é DDL, não DML — e não pode ter WHERE
  • ORDER de execução SQL: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

🏗️
DDL — Data Definition Language

DDL define e modifica a estrutura do banco de dados. Comandos principais: CREATE, ALTER, DROP, TRUNCATE, RENAME.

⭐ DDL vs DML — Resumo
DDL (estrutura): CREATE, ALTER, DROP, TRUNCATE, RENAME
DML (dados): INSERT, UPDATE, DELETE, SELECT (alguns autores incluem SELECT como DQL)
DCL (controle): GRANT, REVOKE
TCL (transação): COMMIT, ROLLBACK, SAVEPOINT

CREATE TABLE

SQL
CREATE TABLE funcionarios (
    id          INT          PRIMARY KEY,
    nome        VARCHAR(100) NOT NULL,
    depto_id    INT,
    salario     DECIMAL(10,2) DEFAULT 0,
    admissao    DATE,
    ativo       BOOLEAN      DEFAULT TRUE,

    -- Chave estrangeira
    CONSTRAINT fk_depto
        FOREIGN KEY (depto_id)
        REFERENCES departamentos(id)
        ON DELETE SET NULL
        ON UPDATE CASCADE
);

ALTER TABLE

SQL
-- Adicionar coluna
ALTER TABLE funcionarios ADD COLUMN email VARCHAR(200);

-- Modificar tipo de coluna
ALTER TABLE funcionarios MODIFY COLUMN salario DECIMAL(12,2);

-- Remover coluna
ALTER TABLE funcionarios DROP COLUMN email;

-- Adicionar constraint
ALTER TABLE funcionarios ADD CONSTRAINT chk_salario CHECK (salario >= 0);

-- Renomear tabela
ALTER TABLE funcionarios RENAME TO colaboradores;

DROP vs TRUNCATE vs DELETE

ComandoCategoriaRemove estrutura?Remove dados?WHERE?Rollback?
DROP TABLEDDL✅ Sim✅ Sim❌❌ Geralmente não
TRUNCATEDDL❌ Não✅ Todos❌❌ Geralmente não
DELETEDML❌ Não✅ Seletivo✅ Sim✅ Sim
⚠️ TRUNCATE é DDL — Pegadinha clássica!
TRUNCATE remove TODOS os registros sem log individual por linha, reinicia contadores AUTO_INCREMENT e geralmente não pode ser revertido com ROLLBACK. Por isso é DDL, não DML. DELETE gera log de cada linha removida e pode ser revertido dentro de uma transação.

✏️
DML — Data Manipulation Language

INSERT

SQL
-- Inserção simples
INSERT INTO funcionarios (id, nome, depto_id, salario)
VALUES (1, 'Ana Silva', 10, 8500.00);

-- Múltiplas linhas
INSERT INTO funcionarios (id, nome, depto_id, salario)
VALUES
    (2, 'Carlos Lima',  20, 7200.00),
    (3, 'Maria Costa',  10, 9100.00),
    (4, 'João Souza',   30, 6800.00);

-- Inserir resultado de SELECT (INSERT INTO ... SELECT)
INSERT INTO historico_salarios (func_id, salario, data)
SELECT id, salario, CURRENT_DATE
FROM funcionarios
WHERE ativo = TRUE;

UPDATE

SQL
-- Atualizar um registro
UPDATE funcionarios
SET salario = salario * 1.10   -- reajuste de 10%
WHERE id = 1;

-- Atualizar múltiplos com JOIN
UPDATE funcionarios f
JOIN departamentos d ON f.depto_id = d.id
SET f.salario = f.salario * 1.15
WHERE d.nome = 'Tecnologia';

-- ⚠️ UPDATE sem WHERE atualiza TODOS os registros!
UPDATE funcionarios SET ativo = FALSE;  -- cuidado!

DELETE

SQL
-- Deletar registro específico
DELETE FROM funcionarios WHERE id = 4;

-- Deletar com subconsulta
DELETE FROM funcionarios
WHERE depto_id IN (
    SELECT id FROM departamentos WHERE ativo = FALSE
);

-- ⚠️ DELETE sem WHERE remove TODOS os registros!
DELETE FROM funcionarios;  -- equivalente ao TRUNCATE, mas com log
💡 Integridade Referencial no DML
Tentar deletar um registro referenciado por FK pode gerar erro. O comportamento depende da opção configurada:
ON DELETE RESTRICT — bloqueia o delete (padrão)
ON DELETE CASCADE — deleta também os registros filhos
ON DELETE SET NULL — define FK como NULL nos registros filhos

SELECT & JOINs

Ordem de Execução da Query SQL

⭐ Ordem lógica de processamento
FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

Por isso: aliases definidos no SELECT não podem ser usados no WHERE (WHERE é processado antes do SELECT).

Schema de Exemplo

Schema
departamentos: id(PK), nome, localizacao
funcionarios:  id(PK), nome, depto_id(FK), salario, cargo
projetos:      id(PK), nome, depto_id(FK), orcamento

Exemplos Práticos de JOIN

SQL
-- INNER JOIN: funcionários COM departamento (exclui sem depto)
SELECT f.nome, d.nome AS departamento
FROM funcionarios f
INNER JOIN departamentos d ON f.depto_id = d.id;

-- LEFT JOIN: TODOS os funcionários (mesmo sem departamento)
SELECT f.nome, d.nome AS departamento
FROM funcionarios f
LEFT JOIN departamentos d ON f.depto_id = d.id;
-- funcionários sem depto aparecem com departamento = NULL

-- Múltiplos JOINs
SELECT f.nome, d.nome AS depto, p.nome AS projeto
FROM funcionarios f
INNER JOIN departamentos d ON f.depto_id = d.id
LEFT JOIN projetos p ON p.depto_id = d.id
WHERE d.localizacao = 'Rio de Janeiro';

-- SELF JOIN: funcionários e seus gerentes (mesma tabela)
SELECT f.nome AS funcionario, g.nome AS gerente
FROM funcionarios f
LEFT JOIN funcionarios g ON f.gerente_id = g.id;
⚠️ Pegadinha — INNER vs LEFT JOIN
A Cesgranrio mostra dados e pergunta qual query retorna tal resultado. Se há funcionários SEM departamento e eles aparecem no resultado com NULL, é LEFT JOIN. Se eles NÃO aparecem, é INNER JOIN. Identifique se há NULLs no resultado — esse é o sinal do LEFT/RIGHT JOIN.

Cláusulas Importantes

SQL
-- DISTINCT: elimina duplicatas
SELECT DISTINCT cargo FROM funcionarios;

-- ORDER BY: ordenação (ASC padrão, DESC reverso)
SELECT nome, salario FROM funcionarios
ORDER BY salario DESC, nome ASC;

-- LIMIT / TOP: limita resultados
SELECT nome, salario FROM funcionarios
ORDER BY salario DESC
LIMIT 5;   -- MySQL/PostgreSQL (TOP 5 no SQL Server)

-- BETWEEN: intervalo inclusivo
SELECT * FROM funcionarios
WHERE salario BETWEEN 5000 AND 10000;

-- IN: múltiplos valores
SELECT * FROM funcionarios
WHERE cargo IN ('Analista', 'Engenheiro', 'Gerente');

-- LIKE: padrão textual
SELECT * FROM funcionarios
WHERE nome LIKE 'Ana%';    -- começa com Ana
-- %Ana%  → contém Ana
-- _Ana   → qualquer char + Ana

GROUP BY e HAVING

SQL
-- Quantidade e média salarial por departamento
SELECT
    d.nome              AS departamento,
    COUNT(f.id)         AS total_func,
    AVG(f.salario)      AS media_salarial,
    MAX(f.salario)      AS maior_salario
FROM funcionarios f
INNER JOIN departamentos d ON f.depto_id = d.id
GROUP BY d.id, d.nome;

-- HAVING: filtra GRUPOS (não linhas individuais)
-- Departamentos com MAIS DE 3 funcionários
SELECT d.nome, COUNT(f.id) AS total
FROM funcionarios f
INNER JOIN departamentos d ON f.depto_id = d.id
GROUP BY d.id, d.nome
HAVING COUNT(f.id) > 3
ORDER BY total DESC;

-- ERRADO: usar WHERE com função de agregação
-- WHERE COUNT(f.id) > 3  ← ERRO de sintaxe!
-- Use HAVING para filtrar por agregação
⭐ Regra de Ouro — GROUP BY
No SELECT, só podem aparecer:
1. Colunas que estão no GROUP BY
2. Funções de agregação (COUNT, SUM, AVG, MAX, MIN)

Se uma coluna aparece no SELECT mas não no GROUP BY e não é agregada → ERRO.

Exemplo Completo

SQL — Questão estilo Cesgranrio
-- "Liste departamentos com média salarial acima de R$ 7.000,
--  mostrando nome do depto, total de funcionários e média,
--  ordenado pela média decrescente."

SELECT
    d.nome                    AS departamento,
    COUNT(f.id)               AS total_funcionarios,
    ROUND(AVG(f.salario), 2)  AS media_salarial
FROM funcionarios f
INNER JOIN departamentos d ON f.depto_id = d.id
WHERE f.ativo = TRUE              -- filtra ANTES do agrupamento
GROUP BY d.id, d.nome
HAVING AVG(f.salario) > 7000     -- filtra GRUPOS
ORDER BY media_salarial DESC;

Subconsultas e Operadores

Subconsultas (Subqueries)

SQL
-- Subconsulta no WHERE com IN
-- Funcionários que trabalham em departamentos de SP
SELECT nome FROM funcionarios
WHERE depto_id IN (
    SELECT id FROM departamentos
    WHERE localizacao = 'São Paulo'
);

-- Subconsulta escalar (retorna 1 valor)
-- Funcionários com salário acima da média
SELECT nome, salario FROM funcionarios
WHERE salario > (SELECT AVG(salario) FROM funcionarios);

-- Subconsulta com EXISTS
-- Departamentos que TÊM funcionários
SELECT nome FROM departamentos d
WHERE EXISTS (
    SELECT 1 FROM funcionarios f
    WHERE f.depto_id = d.id
);

-- Subconsulta no FROM (tabela derivada)
SELECT dept_stats.departamento, dept_stats.media
FROM (
    SELECT d.nome AS departamento, AVG(f.salario) AS media
    FROM funcionarios f
    JOIN departamentos d ON f.depto_id = d.id
    GROUP BY d.id, d.nome
) AS dept_stats
WHERE dept_stats.media > 8000;

Operadores ANY e ALL

SQL
-- ANY: verdadeiro se a condição for V para ALGUM valor
-- Funcionários com salário maior que ALGUM analista
SELECT nome, salario FROM funcionarios
WHERE salario > ANY (
    SELECT salario FROM funcionarios WHERE cargo = 'Analista'
);
-- Equivale a: salario > MIN(salários de analistas)

-- ALL: verdadeiro se a condição for V para TODOS os valores
-- Funcionários com salário maior que TODOS os analistas
SELECT nome, salario FROM funcionarios
WHERE salario > ALL (
    SELECT salario FROM funcionarios WHERE cargo = 'Analista'
);
-- Equivale a: salario > MAX(salários de analistas)

CTEs — Common Table Expressions

SQL
-- WITH (CTE) — query nomeada reutilizável
WITH dept_medias AS (
    SELECT depto_id, AVG(salario) AS media
    FROM funcionarios
    GROUP BY depto_id
),
dept_acima AS (
    SELECT depto_id
    FROM dept_medias
    WHERE media > 8000
)
SELECT f.nome, f.salario
FROM funcionarios f
WHERE f.depto_id IN (SELECT depto_id FROM dept_acima);
